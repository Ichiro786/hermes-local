## v1.0.0-test2: provider sign-in fixes + Hermes v0.23.0 (started 2026-11-06 09:30 IST)
Syed's phone report on test1: Codex stuck on "Starting sign-in…" + "source-update completion failed: an update is still running"; browser opened to ChatGPT "session has ended"; Antigravity button greyed; Hermes app chat: "not connected to any AI provider". Then: build on Hermes v0.23.0; then: check every Hermes-app feature under proot.
- 09:45 Root causes found (reproduced on Hermes v0.23.0 installed in the Hark sandbox, aarch64, /tmp/hsbx):
  - Codex parser: Hermes prints URL and code on their own lines wrapped in ANSI (`\e[94m…\e[0m`). Our URL regex kept `\e[0m` (opened a broken auth.openai.com URL -> ChatGPT "session ended"), the code regex needed "code" on the same line and a word boundary that `m2BNU` breaks -> no code ever shown. Real capture: android/app/src/test/resources/captures/codex-device-v0.23.0-sandbox-arm64.txt.
  - Antigravity greyed: ProvidersScreen had ONE shared `session`; any running flow disabled both buttons (`enabled = !active && session == null`), and the hung Codex flow never ended.
  - Antigravity flow could never work as built: `hermes auth add antigravity-oauth` refuses non-tty stdin; `agy -p` without a session says "authentication required. Run 'agy' to log in"; agy 1.5.1 signs in only from its TUI. Fix: hermes_local_agy_login.py drives agy on a PTY (1000-col window), picks Google OAuth, takes the URL from the OSC 8 link, relays the pasted code, retries on "Got an error", success = token file + `agy models`. Captured on VM (x86_64): captures/agy-login-1.5.1-vm-x86_64.txt.
  - "not connected to any AI provider": nothing set model.provider (default config: provider auto, model anthropic/claude-opus-4.6). Reproduced exactly via /api/ws in the sandbox. Fix: hermes_local_provider.py (ensure/use/models/prune/fallback) using the dashboard's own /api/model/set code (_prepare_main_assignment + _apply_model_assignment_sync). With a stub Codex credential + HERMES_CODEX_BASE_URL stub (scripts/stub-llm.py, Responses API SSE) the /api/ws turn streams "Hello from the Hermes Local stub model." (sandbox).
  - Self-update: v0.23.0 venv_sync.prepare_launch runs a "source-update completion" at launch when updateMechanism=self and the venv looks stale or a pending marker exists; it takes the update lock -> parallel hermes commands print "an update is still running". Fix: install stamp updateMechanism=external (Hermes' Docker image does the same), /etc/hermes/image-provenance.json (makes `hermes update` refuse), AGY_CLI_DISABLE_AUTO_UPDATE=1, stale *.lock removed at build. engine/diag-update.py prints why a launch would update (run in build + smoke + emulator).
