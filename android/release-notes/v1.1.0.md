# Hermes Local 1.1.0

Hermes Local runs your own Hermes Agent server on your Android phone. This release adds **auto-wake**, which starts the local server when you open the official Hermes app. It also moves to the new **engine v0.23.3-1** (Hermes Agent v0.23.3, with a fix for browser tools) and fixes a few long-standing issues.

It installs over Hermes Local 1.0.0 without uninstalling. It is signed with the same key and keeps all your data.

## What's new

### Auto-wake with official Hermes
Turn it on in **Settings > Auto-wake**. When you open the official Hermes app, Hermes Local starts your local server if it is off, so you no longer have to open Hermes Local first.

- **Reuses the normal start.** The lever, the "Open Hermes" button and the notification work as before. An auto-started server behaves exactly like one you started with the lever.
- **Never stops anything.** Leaving the Hermes app, turning the screen off or switching apps never stops the server, so running agent tasks keep going. Only you stop it: the lever, the notification's Stop button, or the existing heat protection.
- **Starts once.** Hermes opens several windows in a row, but auto-wake starts the server once, and never while it is already starting or running. If an auto-start fails, it waits 2 minutes before trying again.
- **Waits until it can start.** It does nothing until the engine is installed and a dashboard password is set, and nothing while the phone is very hot.
- **Status.** Settings shows whether auto-wake is active, needs permission, or was stopped by the system, plus the last time it woke the server. A chip on Home shows it too.

#### Permission and privacy
Auto-wake uses an Android **accessibility service** ("Hermes Local auto-wake"), the only way Android lets an app notice another app coming to the front without asking you each time.

- **One app only.** The system sends it events from the official Hermes app only (`ai.nousresearch.hermes.mobile`), and only "a window came to the front".
- **No screen access.** It cannot read the screen. Window content access is turned off in its configuration. It never types, taps or reads text, and it ignores every other app.
- **Battery.** It is event-driven: no polling, no wake lock, no work while Hermes isn't opened.
- **Opt-in.** Turning auto-wake off in Hermes Local also gives the accessibility permission back.

#### Setup
1. Turn on **Settings > Auto-wake** and tap the status row, then **Open accessibility**.
2. Open **Hermes Local auto-wake** (under Downloaded or Installed apps) and turn it on.
3. On Android 13 or newer, if Android says *Restricted setting*, open **App info**, tap ⋮ (top right), choose **Allow restricted settings**, then try again. Android asks this for apps installed from a file.
4. On ColorOS, OxygenOS or realme UI, also allow Hermes Local to run in the background (App info > Battery). Otherwise the system may turn the service off after a while; Settings then says *Allowed, but not running*.

If Android ever refuses to start the server from the background, Hermes Local shows a *Start Hermes Local?* notification instead. Tap it to start.

## Fixes
- **"Dashboard is not answering" on a healthy dashboard.**
  - Android blocked the app's own health check of `http://127.0.0.1` as plain (cleartext) HTTP. Home showed the warning about two minutes after every start, even though Hermes worked.
  - Cleartext is now allowed for the phone's own loopback address only; everything else stays HTTPS-only.
  - The check uses Hermes' `/api/health` route and re-checks every 5 seconds while the warning is shown.
- **A start could be lost while Hermes was stopping.** Sliding the lever back up during *Stopping* could be ignored, or cut off by the stop finishing. The start now waits for the stop and then runs.
- **Clean up left plugin files behind.**
  - When an old dependency set was deleted, files that proot stores for hard links (`.l2s`) stayed behind, about 400 MB per plugin install from the second one on.
  - Clean up now also removes those files, but only ones nothing uses any more. If it can't tell for sure, it removes nothing.
- **Browser tools.** Hermes' browser tools could not start Chromium inside Hermes Local. Fixed in engine v0.23.3-1; see the engine release notes.

## Improvements
- **New engine: v0.23.3-1.**
  - Hermes Agent v0.23.3 brings upstream fixes for Codex/ChatGPT, MCP servers parked for OAuth, Nous sign-in with a fast clock, and keeping terminal secrets out of session snapshots.
  - Adds the Chromium fix for proot.
- The engine log names how Hermes was started (`source=auto-wake`), and records why a health check failed.

## Compatibility
- Android 10 (API 29) or newer, arm64 phones.
- Package `dev.syed.hermeslocal`, signed with the same certificate as every earlier Hermes Local build. It installs over 1.0.0 (versionCode 17 and later) without uninstalling.
- Auto-wake reacts to the official Hermes app, `ai.nousresearch.hermes.mobile`: the Android beta Nous Research distributes through Firebase App Distribution. Other Hermes clients still work with Hermes Local; they just don't trigger auto-wake.

## Upgrade notes
- **One-time engine download (about 650 MB).** On first launch after the update, Hermes Local downloads engine v0.23.3-1 and replaces the old engine. Use Wi-Fi if you can; an interrupted download resumes. The server stays off during the update; start it again afterwards.
- **Your data is kept.** This covers your dashboard password, config and API keys, the Codex/Claude/Nous/Antigravity sign-ins, sessions, memories, skills, cron jobs, plugins and their settings, MCP servers and your files.
- **Python dependencies are rebuilt.** The engine's Python dependencies are replaced by the new engine's. Hermes reinstalls plugin dependencies when needed. Afterwards, Settings > Storage > Clean up removes what the old engine left behind.
- **Auto-wake is off** until you turn it on.

## Known issues
- **Not tested on a real phone yet.** Testing used the Android emulator in CI (Android 16 / API 36, x86_64). Auto-wake, the background start and the browser fix were not tested on a physical Android 17 or ColorOS phone. Vendor battery managers may stop the accessibility service; Settings shows this, and the notification fallback covers a refused start.
- **Browser profile settings.** Chromium under proot on Android cannot save some of its own settings files. Hermes' disposable browser sessions work; a persistent browser profile may not keep its settings. The first browser start can take a while.
- **Stub accounts only.** Real Codex, Claude, Nous, Antigravity, GPT-Live and Gemini Live accounts were not used in testing (stub or rejected credentials only).
- **Data after a plugin install.** After you install a plugin, your data stays about 200 MB larger even after Clean up. That is the new, unslimmed dependency set Hermes builds on the phone, not leftovers.
- **Beta availability.** The official Hermes Android beta is distributed by Nous Research through Firebase App Distribution and was reported full in November 2026.
